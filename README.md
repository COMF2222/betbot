# Betbot

Telegram-бот для анализа профессиональных карт Dota 2 после драфта. Админка — команды и кнопки в Telegram. Пост — карточка с короткой подписью: победитель карты, вероятность, звёзды, две причины и цены рынка. Результат приходит ответом на исходный прогноз; подробный разбор доступен в админке.

## Что реализовано

- Админка в одном сообщении: текущие турниры, поиск, выбранные события и архив, понятные «Назад» и «Главная», цветные кнопки публикаций. Несколько групп и каналов могут получать посты одновременно; каждое место включается отдельно.
- Steam Web API + OpenDota: live-драфты, игроки и герои, номера карт, результаты. OpenDota также даёт историю для обучения.
- Polymarket: каталог Dota 2, явные привязки, отдельные рынки карт, отображаемая цена рынка и отдельно цена покупки; поддержка CTF и V2, минутная история цен.
- Две обучаемые модели вероятности: игроки + драфт и только драфт. Калибровка на более позднем периоде, итоговый тест ещё позднее; карты одной серии не разделяются между наборами.
- Подробный разбор: контрпики, связки предполагаемых позиций 1+5 и 3+4, отдельный мид-матчап, число наблюдений и экономика прошлых игр к 10-й минуте. Для новых или неоднозначных ролей бот показывает неизвестность. Набор `detailed` позволяет проверить вклад этих признаков отдельно; рабочая модель остаётся `classic`, поскольку сравнительный тест не подтвердил улучшение.
- Отдельная экспериментальная модель длительности. При наличии линии в подключённом источнике — вероятности ТБ/ТМ.
- SQLite с WAL: снимки данных, версии прогнозов, результаты и журнал отправок. Промахи не удаляются; неоднозначная отправка не повторяется автоматически.
- Собственный дизайн BETBOT: горизонтальные составы, крупная основная оценка, отдельная оценка драфта и цены обеих команд. Дневные и недельные отчёты — изображение с подписью, статистика и CSV.
- Сравнение итогов с парными котировками на ту же карту, учёт прогнозов против рынка и наблюдавшихся камбэков. Без сохранённой истории цен камбэк не добавляется.
- Проверяемый JSON-контракт для котировок 1win, BetBoom, Winline и PARI; адаптер явно привязанных рынков OddsPapi. Рабочие прямые подключения этих четырёх букмекеров пока не подтверждены. До подключения проверенного источника цены берутся только с Polymarket.

## Запуск локально

Нужны Python 3.12+ и `uv`.

```powershell
uv sync --extra dev --python 3.12
# .env уже создан. Копируйте шаблон только если своего .env ещё нет.
if (!(Test-Path .env)) { Copy-Item .env.example .env }
```

В `.env` укажите `TELEGRAM_BOT_TOKEN` из BotFather и свои числовые Telegram ID в `ADMIN_IDS` (через запятую). Если ID неизвестен: заполните токен, отправьте своему боту `/start`, выполните `uv run betbot telegram-id` и перенесите свой ID в `ADMIN_IDS`. Эта команда читает личные сообщения без запуска основного worker. Не запускайте её одновременно с работающим ботом. Основной процесс не стартует с пустым списком администраторов.

В этом рабочем каталоге уже обучена модель на 20 000 про-картах и сохранены исторические отчёты. Для первого запуска повторять обучение и загрузку истории не требуется:

```powershell
uv run betbot run
```

Следующие команды нужны для обновления данных и повторения проверки:

```powershell
uv run betbot doctor --check-bookmakers
uv run betbot train --limit 5000
uv run betbot backtest --months 4 --limit 20000
uv run betbot demo --with-assets
uv run betbot demo --report --output artifacts/demo-day.png
uv run betbot run
```

Отчёт проверки источников: `data/source-audit.json`. Обученная модель: `data/model.json`. Результаты её временной проверки: `data/model-report.json`. Демонстрационные карточки: `artifacts/demo.png` и `artifacts/demo-day.png`; они явно обозначены как условные и не входят в статистику. В Telegram `/demo` также позволяет посмотреть пример итогов дня.

Для обучения из уже сохранённых данных:

```powershell
uv run betbot train --input data/training-data.json
```

## Историческая проверка за четыре месяца

`betbot backtest --months 4` отдельно обучает модель только на истории до начала этих четырёх календарных месяцев. Веса и калибровка затем фиксируются. Для каждой карты сохраняются вход без результата, прогноз и отдельный фактический исход. Модель получает только драфт и участников.

По умолчанию рейтинги команд/игроков и статистика драфтов обновляются по уже завершённым предыдущим играм, с буфером 60 секунд: так работает последовательная проверка по времени. Параллельно идущие карты не влияют до завершения. У рабочего бота эти обновления сохраняются в SQLite и переживают перезапуск. Веса моделей остаются фиксированными до следующего обучения. Чтобы скрыть от модели даже результаты предыдущих карт всего тестового периода, используйте `--static-history`.

Исторический тест обновляет историю по предыдущим доступным про-картам всех лиг; worker обновляет её по наблюдаемым картам включённых турниров. Остальная новая история попадает в рабочего бота при следующем `train`. Это различие нужно учитывать при сравнении исторического процента и будущей статистики.

```powershell
uv run betbot backtest --months 4 --input artifacts/backtest/dataset.json --static-history --output artifacts/backtest-static
```

Результаты: `artifacts/backtest/report.md`, `report.json`, `results.csv`. Отдельные файлы: `blind-inputs.jsonl` (без победителей и длительности), `predictions.jsonl` (без исходов), `outcomes.jsonl` (цели проверки), `frozen-model.json` (модель до теста). Отчёт показывает все карты, сигналы, точность и объём по уверенности, результаты по турнирам и сравнение с Elo. Модель рабочего бота при этом не заменяется.

`analyses.jsonl` содержит признаки, предполагаемые роли и справочные наблюдения каждого прогноза. Для точного повторения границы используйте `--end 2026-10-10T18:00:00+03:00` с нужным временем из `requested_end` сохранённого отчёта.

Эта проверка ретроспективная; часть периода уже изучалась при разработке. Следующие новые прогнозы нужны для независимой проверки улучшений. Подбирать порог или гиперпараметры по итоговому отчёту нельзя — для этого используется более ранний калибровочный период.

### Только Tier 1

```powershell
uv run betbot backtest --months 4 --input artifacts/backtest/dataset.json --league-list config/tier1-2026.json --output artifacts/backtest-tier1
```

Список событий, их даты, OpenDota league ID, источники классификации и исключения находятся в `config/tier1-2026.json`. В проценте учитываются только основные события; квалификации исключены. История предыдущих завершённых карт других лиг может использоваться для рейтингов. Обучение до периода проверки использует все доступные про-карты.

Отдельный эксперимент со сменой состава:

```powershell
uv run betbot backtest --months 4 --input artifacts/backtest/dataset.json --league-list config/tier1-2026.json --feature-set roster --output artifacts/backtest-tier1-roster
```

Он добавляет долю сохранившихся игроков и отдельную оценку рейтинга текущего состава, не подменяя базовый рейтинг. Этот эксперимент не заменяет модель рабочего бота автоматически.

Для контрпиков, связок по предполагаемым позициям и мида используйте `--feature-set detailed` с обогащённой историей `data/detailed-history.json`. Обогащение получает только показатели прошлых завершённых игр. Текущие GPM, линии и золото не передаются модели; позиции текущих игроков выводятся по последним 20 прошлым наблюдениям, минимум 5 игр и 70% согласованности. Gold10 — накопленное заработанное золото, а не net worth; учитывается только точный момент 600 секунд. Статистика разделена по крупным патчам OpenDota, без выдуманных данных о буквенных патчах.

Сравнение на одних и тех же 442 картах: `artifacts/draft-comparison/report.md`. Основной актуальный исторический отчёт: `artifacts/draft-comparison/classic/report.md`. Копии отчёта и CSV находятся в `data/reports/tier1` и доступны через `/history` в личном чате бота. В сохранённой проверке базовая модель дала 64,5% на всех картах; `detailed` — 63,8%. Улучшение подробными признаками пока не подтверждено, поэтому они остаются справочными в основном разборе. Они не объявляются причиной победы или доказанным выигрышем линии.

Команда обучения атомарно заменяет файл модели, worker подхватывает новую версию. Запускайте одно обучение одновременно и храните отчёты предыдущих версий для сравнения. Отложенный тест нужен для оценки, а не для подбора гиперпараметров по его результатам.

## Первое подключение в Telegram

1. Напишите боту `/start` в личном чате.
2. Откройте «🏆 Текущие турниры», выберите событие и нажмите «Отслеживать турнир». Поиск работает внутри выбранной вкладки. Все старые события доступны отдельно во вкладке «Весь каталог».
3. Подключите места публикации через «📣 Куда публиковать». Для группы разрешите боту сообщения и фотографии; `/bind` из группы/темы добавляет её. Для канала назначьте бота администратором с правом «Публикация сообщений», затем в личном чате нажмите «＋ Канал» и выберите его кнопкой Telegram. Можно подключить группу и канал одновременно, включая закрытый канал без публичного адреса. Публичный канал также добавляется командой `/bind @channel` в личном чате.
4. В личном чате найдите событие `/markets НАЗВАНИЕ КОМАНДЫ`. Для автоматического сопоставления выбранного турнира задайте `/polyfilter LEAGUE_ID ТЕКСТ_ТУРНИРА_В_ЗАГОЛОВКЕ`.
5. Для точного номера карты при возможности задайте `STEAM_API_KEY` в `.env`. Альтернатива: `/map MATCH_ID НОМЕР` и `/market MATCH_ID EVENT_ID`, затем `/refresh MATCH_ID`, пока драфт свежий. Различия названий команд задаются через `/alias`.
6. Посмотрите `/model` и `/status`. Предварительные карточки появляются в личном чате; `/pending` показывает сохранённые версии.
7. В `/admin` включите автопубликацию. Она разрешается после проверки модели: минимум 200 тестовых карт и Brier лучше базового Elo. Это технический порог первого выпуска, а не доказательство доходности. Ручная публикация проходит те же проверки.

`/history` присылает исторический отчёт и CSV. `/threshold 0.55` меняет минимальную вероятность новых сигналов; повышение порога уменьшает число прогнозов. Порог 60% в историческом отчёте не является обещанием будущих 70% успешных исходов. `/position MATCH_ID ACCOUNT_ID 1–5` подтверждает известную вам роль только на этой карте; затем `/refresh MATCH_ID` пересобирает свежий предварительный прогноз. Опубликованный прогноз не заменяется.

При запуске бот регистрирует меню команд в Telegram: полный список в личном чате администратора и `/bind` в группе. В личном чате также понимает «старт», «меню», «лиги» и «турниры НАЗВАНИЕ». Навигация кнопками обновляет текущую панель; карточки и скачиваемые файлы приходят отдельными сообщениями. В группе отправляйте `/bind@ИМЯ_ВАШЕГО_БОТА`, чтобы команда точно адресовалась ему при включённом privacy mode.

Команду подключения канала отправляйте в личном чате: посты в самом канале могут быть анонимными и не подтверждают личность администратора. Перед подключением бот проверяет доступ и право публикации. Проверка не отправляет пробные сообщения. Выбор кнопкой Telegram отменяется через `/cancel`. Подключение нового места сохраняет остальные; старую одиночную привязку бот перенесёт автоматически при первом запуске обновлённой версии. Настройки `TELEGRAM_CHAT_ID` и `TELEGRAM_TOPIC_ID` остаются для первого переноса старой конфигурации; дальнейшее управление — через админку.

Прогноз считается один раз, даже если опубликован в нескольких местах. В каждом месте сохраняется свой ID поста и темы: результат отвечает именно на него. Итоги канала или группы включают только дошедшие туда прогнозы. Новый канал не получает задним числом старые прогнозы. Отключение места останавливает новые посты и ответы до повторного включения; уже опубликованные сообщения сохраняются. Сбой в одном месте не блокирует остальные.

Текущие турниры определяются по подтверждённым датам, свежим live-снимкам и завершённым про-матчам сегодня по МСК. Порядок league ID не используется как календарь. Список перепроверяется каждые 5 минут; кнопка «Обновить» запускает проверку сразу. Устаревший live-снимок не получает статус «Сейчас есть матч». Проверенный календарь поставляется в `src/betbot/resources/tournament-calendar.json`; свой файл с такой же схемой можно задать в `config/tournament-calendar.json`. После окончания дат событие автоматически уходит из текущих, если новых матчей нет. Добавляйте новые даты только после проверки расписания организатора.

## Telegram не отвечает / VPN и прокси

`Run polling` подтверждает начало подключения. Если позже видны `TelegramNetworkError` и `Request timeout error` в `message.answer`, обработчик получил команду, но ответ не дошёл через сеть. Менять PowerShell на VS Code само по себе это не исправляет: соединение устанавливает Python.

Если VPN предоставляет локальный HTTP/SOCKS5 прокси, задайте в `.env` его реальный адрес и порт:

```dotenv
TELEGRAM_PROXY_URL=http://127.0.0.1:2080
```

Это пример порта; используйте адрес из своего VPN-клиента. `TELEGRAM_PROXY_URL` применяется только к Telegram. `PROXY_URL` задаёт общий прокси для Telegram, OpenDota и Polymarket. Для SOCKS5 URL выглядит как `socks5://127.0.0.1:1080`. Без явной настройки Telegram также учитывает `HTTPS_PROXY`, `ALL_PROXY`, `HTTP_PROXY` и исключение `NO_PROXY` из среды процесса. Адреса с логином/паролем выводятся в журнал без этих данных.

После изменения `.env` или обновления кода остановите бота через Ctrl+C и запустите `uv run betbot run` снова. VPN/локальный прокси должен оставаться запущенным. `uv run betbot doctor` проверяет Telegram и меню администратора без отправки сообщений и без конкуренции с polling. Не запускайте второй `betbot run` или `telegram-id` одновременно с первым процессом: два потребителя обновлений конфликтуют.

`is not handled` может относиться к служебному обновлению или неподдерживаемой команде; сама строка не доказывает отсутствие соединения. Сетевые сбои ответов теперь записываются кратко и видны в `/status`; отправка не повторяется автоматически.

Публикации не работают без токена, прав бота в подключённых группах и каналах, выбранных турниров, своевременных данных и обученной модели. Полностью устаревший или неполный драфт не заменяется выдуманным прогнозом.

## Данные и практические ограничения

Worker независимо опрашивает OpenDota и Steam (`GetLiveLeagueGames` и `GetTopLiveGame`), объединяет карты по ID и проверяет команды и героев. Сбой одного источника не блокирует другой. Задержка DotaTV относится к транслируемой статистике; она не прибавляется к текущим часам `TopLiveGame`. Для часов из задержанного scoreboard учитывается задержка. В Steam API без времени обновления отдельно сохраняется время прямого чтения; это не доказательство отсутствия задержки телеметрии.

По умолчанию публикуются все полные драфты выбранных турниров. Оценки ниже порога помечаются как ровная карта. В «Публикациях» можно переключиться на «только сигналы». Если данные получены уже по ходу карты, публикуется явно помеченный разбор с задержкой: только герои и составы, без текущих убийств, золота, позиции и результата. Его результаты и отчёты считаются отдельно от своевременных прогнозов. Можно отключить такие разборы. Устаревшие, неполные и конфликтующие данные, а также известные завершённые карты не публикуются. Покрытие и причины пропусков видны в `/status` и на странице турнира; абсолютное покрытие бесплатными API не гарантируется.

Номер карты и соответствие рынку должны быть подтверждены. Прогноз может существовать без цены, если в Polymarket отсутствует нужная карта или нет надёжной привязки. Публичный кэф — обратная отображаемая цена Polymarket: midpoint при спреде до 10 центов, иначе последняя сделка. Ask-цена покупки хранится отдельно и используется для оценки ожидания в админском разборе. Полученные позже цены добавляются в тот же пост с отметкой времени; первоначальный прогноз не переписывается.

Утренние анонсы выбранных матчей работают в 10:00 МСК, когда источник даёт подтверждённое расписание. Настройки: `MORNING_BRIEF_ENABLED` и `MORNING_BRIEF_HOUR`; включение доступно в разделе публикаций. Результаты последней проверки пяти улучшений модели: [отчёт](docs/model-upgrades-2026-10-11.md). Текст для закрепа: [BETBOT](docs/channel-post.md).

Проценты — результат обученной модели. Звёзды показывают диапазон вероятности фаворита: <55% — 0; 55–60% — 1; 60–65% — 2; 65–70% — 3; 70–80% — 4; от 80% — 5. Это сила сигнала, а не гарантия точности. «Тест: N из 100» — фактическая доля верных исходов в соответствующем диапазоне на прошлом временном тесте всех про-лиг; рядом указан объём `n`. Число показывается только при наличии минимум 100 тестовых карт в диапазоне. Для остальных случаев указано, что частота не подтверждена. Эти сведения сохраняются вместе с прогнозом и не меняются после результата. Точность Tier 1 проверяется отдельно; исторических коэффициентов для измерения доходности пока нет.

По умолчанию в 23:00 МСК приходит предварительная карточка текущего дня. После закрытия календарного дня и подтверждения результатов бот отправляет итоговую карточку. При выборе 00:00 или 04:00 первая карточка относится к предыдущему дню. Повторная отправка той же версии защищена журналом доставок. Надёжного расписания для отправки точно после последнего матча пока нет. Недельный отчёт — понедельник, 12:00 МСК. Часы меняются в «Публикации → Время отчётов» или `/reports 23 12`. Старые сохранённые настройки времени сохраняются.

В отчёте отдельно считаются основная оценка и только драфт; ровная оценка 50/50 не считается выбором победителя для драфта. В сравнении с рынком используются только карты с котировками обеих сторон и одинаковыми правилами расчёта; вероятности нормализуются из обратных коэффициентов и остаются приближением. Камбэк отмечается лишь при сохранённой во время игры паре цен с вероятностью будущего победителя не выше 15%. История собирается после публикации прогноза, поэтому минимум за весь матч может остаться ненаблюдённым. Это сравнение точности, а не отчёт о доходности.

При сетевой ошибке Telegram неизвестно, был ли пост доставлен. Запись имеет статус `uncertain`; после проверки поста используйте `/confirm ID forecast MESSAGE_ID CHAT_ID`. Аналогично для результата. Если неоднозначная отправка одна, `CHAT_ID` можно не указывать; для нескольких его нужно взять из раздела «Состояние». Журнал отделяет отправки по месту: неоднозначная отправка не повторяется, а подтверждённая не блокирует результат в другом канале или группе. После перезапуска недоставленная часть плана продолжается только пока драфт ещё свежий.

SQLite рассчитан на один процесс бота. Не запускайте несколько worker поверх одной базы. Для резервной копии остановите процесс и скопируйте весь каталог `data` либо используйте штатный SQLite backup API.

## Docker

Для сервера с уже работающим Mihomo используйте [пошаговую инструкцию](docs/deploy-mihomo.md) и `bash deploy.sh setup`, затем `bash deploy.sh start`. Скрипт подключает отдельный контейнер BETBOT к существующему прокси и сохраняет настройки другого проекта. В GitHub находятся исходники; токен и обученная модель с базой переносятся личным архивом.

```powershell
docker compose build
docker compose run --rm betbot betbot doctor
docker compose run --rm betbot betbot train --limit 5000
docker compose up -d
```

Образ работает от пользователя `10001:10001`. Каталог `data` должен быть доступен ему на запись; `deploy.sh setup` исправляет владельца этого каталога одноразовым контейнером. `.env`, `.secrets`, `deploy.env` и `data` не добавляйте в Git. Внешние порты не нужны: используется polling Telegram.
