# Подключение дополнительных площадок

В проекте нет выдуманных прямых API 1win, BetBoom, Winline или PARI. Площадка появляется в карточке только после получения проверенных котировок. До этого работает Polymarket. Все пять источников доступны в настройках Telegram, но кнопка включения не создаёт подключение.

## Контракт JSON-источника

Задайте `ODDS_FEED_URL` и, если нужен, `ODDS_FEED_API_KEY` в `.env`. Бот делает GET с `match_id` в query и передаёт ключ в `Authorization: Bearer …`. Источник должен уже иметь подтверждённое соответствие своей игры Dota match ID.

Пример формата (числа условные):

```json
{
  "quotes": [{
    "source": "BetBoom",
    "match_id": "1234567890",
    "market": "map_winner",
    "outcome": "radiant",
    "odds": 1.85,
    "observed_at": "2026-10-10T15:00:00Z",
    "source_updated_at": "2026-10-10T15:00:00Z",
    "map_number": 2,
    "line": null,
    "rules": "verified-map-winner-rules-v1",
    "active": true,
    "url": "https://example.com/event/123",
    "gross": false,
    "liquidity": null,
    "market_id": "source-market-123"
  }]
}
```

`source_updated_at` в этом контракте — время подтверждённого наблюдения у источника. Это не просто время последнего движения цены. Кэш нельзя обновлять новым временем без нового наблюдения линии.

Допустимые `source`: `1win`, `BetBoom`, `Winline`, `PARI`. Исходы победителя: `radiant`, `dire`. Для `duration_total`: `over`, `under`, а `line` задаётся в минутах. ТБ 38.5 сравнивается только с ТБ 38.5 по тем же правилам. Неверные и устаревшие записи отклоняются.

`rules` — идентификатор проверенной совместимости условий расчёта. Разные условия должны иметь разные значения. `gross=true` обозначает предварительную цену до неизвестных расходов. Такие записи не выбираются лучшими в одной группе с ценами, где расходы учтены.

## OddsPapi

OddsPapi (`oddspapi.io`) и The Odds API (`the-odds-api.com`) — разные поставщики. `ODDSPAPI_API_KEY` принимает только ключ OddsPapi. Ключ The Odds API хранится отдельно как `THE_ODDS_API_KEY` и используется диагностикой `betbot doctor` для проверки покрытия. Проверка `/v4/sports?all=true` 14 октября 2026 вернула 180 записей без Dota 2 или других киберспортивных дисциплин. Адаптер котировок Dota 2 для этого сервиса не включён; ключ не отправляется в OddsPapi. Само наличие рабочего ключа не подтверждает наличие нужного рынка.

В проекте есть клиент каталога букмекеров и адаптер явно привязанных рынков. Для использования нужен ключ поставщика и подтверждение покрытия конкретных брендов/рынков. `betbot doctor` сохраняет доступный каталог в `data/bookmakers.json`, если ключ задан.

Команда `/oddsbind MATCH_ID JSON` принимает одну привязку либо массив:

```json
{
  "source": "PARI",
  "fixture_id": "VERIFIED_FIXTURE_ID",
  "bookmaker_key": "VERIFIED_BOOKMAKER_KEY",
  "market_id": "VERIFIED_MARKET_ID",
  "map_number": 2,
  "market": "map_winner",
  "outcomes": {"radiant": "VERIFIED_OUTCOME_ID", "dire": "VERIFIED_OUTCOME_ID"},
  "rules": "verified-map-winner-rules-v1"
}
```

Ключи в примере обозначают места для реальных ID, а не работающий пресет. Адаптер требует `observedAt` у записи/букмекера. Если тариф отдаёт только `changedAt`, время свежего наблюдения не подтверждено и запись отклоняется; можно подключить источник по JSON-контракту после проверки его свежести. Реальное покрытие всех четырёх площадок этим поставщиком пока не установлено.

## Polymarket

Поиск событий использует каталог Dota 2. Для V2 используются `positionIds`, для CTF — `clobTokenIds`. Рыночный ориентир и цена покупки (`1 / ask`) сохраняются отдельно: публичная карточка показывает ориентир, виртуальный банк использует исходную цену покупки. Подробности, включая условное использование рынка серии для решающей карты, — в [описании банка](paper-bank.md).

Привязка безопасна в двух режимах:

- `/market MATCH_ID EVENT_ID` после проверки события администратором;
- `/polyfilter LEAGUE_ID ЧАСТЬ НАЗВАНИЯ ТУРНИРА` вместе с единственным совпадением обеих команд и времени события. Неоднозначные совпадения пропускаются.

Для номера карты используется поле live-источника, необязательный `STEAM_API_KEY` или `/map MATCH_ID НОМЕР`. Номер не угадывается из активных ставок на следующую карту. Без подтверждённого номера бот ждёт следующего обновления до создания прогноза и ставки банка.

Разные названия команд задаются через `/alias TEAM_ID ИМЯ НА POLYMARKET`. Если предварительный прогноз уже создан, `/refresh MATCH_ID` сохраняет новую предварительную версию, оставляя старую в истории. Опубликованные прогнозы неизменны.
