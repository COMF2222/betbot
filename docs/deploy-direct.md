# Сервер без VPN

На сервере в Финляндии бот подключается к Telegram, Steam, OpenDota и Polymarket напрямую. Нужны Docker Engine и Docker Compose. Каталог `data` и `.env` содержат данные приложения и ключи; в GitHub их нет.

Первый запуск после загрузки ключей и моделей:

```bash
cd /root/betbot-server
bash deploy.sh setup-direct
bash deploy.sh start
bash deploy.sh status
```

`setup-direct` сохраняет режим в `deploy.env`, собирает образ и проверяет источники без публикации постов. Все последующие команды используют сохранённый режим. Бот запускается автоматически после перезагрузки сервера; его лимиты — 1 CPU и 1 ГБ памяти.

```bash
bash deploy.sh logs
bash deploy.sh check
bash deploy.sh restart
bash deploy.sh stop
```

Обновление исходников с сохранением базы и ключей:

```bash
git pull --ff-only
docker compose --project-name betbot --env-file deploy.env -f compose.yaml -f compose.direct.yaml build betbot
bash deploy.sh restart
```

На новом сервере настроен отдельный ключ GitHub с доступом только на чтение этого репозитория. Исходники доступны через SSH GitHub на порту 443. Личный токен GitHub на сервер не переносится.

Резервные копии:

```bash
python3 scripts/backup_server.py
ls -lh /root/betbot-backups
```

Архив содержит согласованную копию базы, модели, данные и ключи `.env`; храните его приватно. По умолчанию сохраняются семь последних архивов. На сервере настроен ежедневный запуск в 04:15 МСК. Копию следует также скачивать на другой компьютер: локальные архивы не защищают от потери самого сервера.

При восстановлении из выгрузки прогнозов вместо полной базы старые карточки могут не иметь ID Telegram-сообщений. Такие доставки помечаются `archived`: они сохраняются в статистике, но бот не переотправляет карточки и не пытается отвечать на потерянные ID. Новые прогнозы используют обычный журнал доставок и ответы к исходным постам.
